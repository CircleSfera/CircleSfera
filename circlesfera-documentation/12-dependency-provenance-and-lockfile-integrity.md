# 12 — Dependency Provenance & Lockfile Integrity

**Status:** ✅ Implemented  
**Owners:** Platform Engineering  
**Reviewed:** 2026-09-17

---

## Purpose

Supply-chain attacks against npm packages are a realistic threat vector. A tampered `package-lock.json`
can silently install malicious code even when source files are clean. This document establishes
CircleSfera's policy for verifying lockfile integrity and dependency provenance before any
`npm install` or `npm ci` is executed — both locally and in CI.

---

## Policy

1. **All workspaces use lockfileVersion 3.** Lockfiles generated by older npm versions (v1, v2) are
   rejected outright.
2. **Only the official npm registry is allowed.** Packages resolved from any other host
   (`https://registry.npmjs.org/` is the sole allowlisted registry) will fail the check.
3. **Every installable package must carry a sha512 SRI integrity hash.** Exceptions apply only to:
   - Bundled packages (`inBundle: true`).
   - Local workspace symlinks resolved via relative paths (`../…` or `file:…`).
4. **No legacy override fields.** Packages containing `_resolved` or `_integrity` fields (npm v1
   artifact) are rejected as they can shadow the canonical integrity hash.
5. **All declared dependencies must be present in the lockfile.** A `package.json` dependency
   missing from the lockfile packages map is flagged as a phantom dependency.
6. **Integrity hashes must be well-formed sha512 SRI strings.** The format `sha512-<base64>` is
   enforced by regex.
7. **Registry spot-checks (optional).** When run outside CI (`npm run verify:lockfiles`), 5 packages
   per workspace are spot-checked against the live npm registry to verify that the lockfile hash
   matches the published tarball hash. This catches post-publication registry mutations.

## Implementation

### `scripts/verify-lockfile-integrity.mjs`

Performs all 7 checks above across all 4 workspaces. Exits non-zero on any error.

```bash
# Structural checks only (CI mode — no outbound network)
npm run verify:lockfiles:fast

# Full check including npm registry spot-checks (local/pre-release)
npm run verify:lockfiles
```

Both scripts are registered in the root `package.json`:

```json
"verify:lockfiles":      "node scripts/verify-lockfile-integrity.mjs",
"verify:lockfiles:fast": "node scripts/verify-lockfile-integrity.mjs --skip-signatures"
```

### CI Integration

The lockfile integrity check runs **before `npm ci`** in `.github/workflows/ci-quality.yml`:

```yaml
- name: "Dependencies: Verify Lockfile Integrity & Provenance"
  run: npm run verify:lockfiles:fast

- name: Install Monorepo Dependencies
  run: npm ci
```

Running it before installation ensures that a tampered lockfile is caught before any malicious
package is installed into the CI runner.

## Checks Reference

| # | Check | Fail condition |
| - | :---- | :------------- |
| 1 | lockfileVersion | Not equal to `3` |
| 2 | Registry allowlist | `resolved` URL not under `https://registry.npmjs.org/` |
| 3 | Integrity present | No `integrity` field on non-bundled, non-local package |
| 4 | No legacy overrides | `_resolved` or `_integrity` field present |
| 5 | Well-formed sha512 SRI | Integrity string does not match `^sha512-[A-Za-z0-9+/]+=*$` |
| 6 | Declared deps in lockfile | `package.json` dep has no `node_modules/<dep>` entry in lockfile |
| 7 | Registry spot-check | Lockfile hash differs from npm registry `dist.integrity` |

---

## Responding to Failures

| Failure | Likely cause | Resolution |
| :------ | :----------- | :--------- |
| Non-allowlisted registry | Internal mirror, Verdaccio, private registry | Add to `ALLOWED_REGISTRIES` with explicit approval, or migrate package |
| Missing integrity hash | npm <7 used to install, or manual lockfile edit | `npm install` with Node 18+ / npm 9+ in affected workspace |
| Integrity mismatch (spot-check) | Registry mutation, lockfile tampered, or package republished | Run `npm install` fresh and verify diff; escalate if unexpected |
| Phantom dependency | `package.json` dep not resolved (optional/peer not installed) | Run `npm install` to reconcile; suppress with comment if intentional peer dep |

> [!CAUTION]
> An **integrity mismatch** from the registry spot-check (check 7) must be treated as a potential
> supply-chain incident until proven otherwise. Do not proceed with the release until the root cause
> is confirmed.

---

## Exemptions

- **Local workspace symlinks** (`../circlesfera-shared`) have no tarball and therefore no integrity
  hash. This is expected and suppressed silently.
- **Bundled packages** (`inBundle: true`) are part of a parent tarball and also have no independent
  integrity hash.
